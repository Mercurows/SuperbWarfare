# Distant Vehicle Sync — дальняя видимость техники (поверх Voxy LOD)

**Дата:** 2026-07-06
**Репозиторий:** SuperbWarfare-fork-PJM (NeoForge 21.1.x, MC 1.21.1, Kotlin)
**Статус:** дизайн утверждён

## Проблема

Техника SBW не видна дальше серверного view distance: ваниль ограничивает
эффективный tracking range энтити величиной `(viewDistance - 1) * 16` блоков
(`ChunkMap.TrackedEntity`), поэтому `setTrackingRange(512)` в `ModEntities.kt`
фактически не работает. При этом с Voxy террейн виден на километры, и техника
«исчезает» посреди видимого ландшафта.

Voxy энтити не рендерит и менять его не нужно: он лишь рисует LOD-террейн и
пишет глубину до энтити-прохода, так что дальняя техника, отрисованная штатным
энтити-пайплайном, корректно перекрывается рельефом.

## Решение

Собственный S2C-канал синхронизации «дальней техники» целиком внутри
SBW-форка. Сервер периодически шлёт компактные снапшоты техники в радиусе R,
клиент держит локальных «призраков» (реальные инстансы классов техники, не
добавленные в `ClientLevel`) и рендерит их существующим `SbmVehicleRenderer`
(LOD-модели уже есть: `RenderDistanceHelper.shouldRenderLOD`, порог 32 блока).

Ограничение (принято): сервер знает только о технике в прогруженных чанках
(рядом с игроками или force-loaded). Техника в непрогруженных чанках не
существует и не синхронизируется.

## Компоненты

### 1. Сервер — `DistantVehicleTracker`

Обработчик server tick (`ServerTickEvent.Post` или level tick):

- Раз в `distantVehicleSyncInterval` тиков для каждого `ServerPlayer`:
  - Собрать все `VehicleEntity` уровня игрока в радиусе
    `distantVehicleSyncRadius` блоков (горизонтальная дистанция).
  - Технику в ванильном tracking range НЕ исключать на сервере — во
    внутренности `ChunkMap` не лезем; дедупликация целиком на клиенте
    (снапшот техники, которая уже есть в `ClientLevel`, просто не
    рендерится). Лишний трафик пренебрежим.
  - Отправить `DistantVehiclesMessage` — авторитетный полный список
    снапшотов техники в радиусе (плюс поле `interval`, чтобы клиент знал
    таймаут устаревания). Призрак, отсутствующий в очередном списке,
    удаляется на клиенте. Сервер полностью stateless — никакого
    состояния на игрока.

Снапшот одной единицы техники:

| Поле | Тип | Источник |
|---|---|---|
| entityId | Int | `entity.id` (ванильный network id) |
| typeId | Int/ResourceLocation | registry id `EntityType` |
| x, y, z | Double×3 | позиция |
| yaw, pitch | Float×2 | поворот корпуса |
| turretYRot, turretXRot | Float×2 | `VehicleEntity.turretYRot/turretXRot` |
| skinId | String | `VehicleEntity.skinId` (пустая строка = дефолт) |

Кодек — через существующую kotlinx-serialization инфраструктуру
(`PacketPayload` + `playToClient<...>()` в `NetworkRegistry.kt`).

### 2. Конфиг — дополнение `VehicleConfig.kt`

- `distant_vehicle_sync_radius` — блоки, default 1500, range 0..10000;
  0 = функция выключена (пакеты не шлются вовсе).
- `distant_vehicle_sync_interval` — тики между рассылками, default 10,
  range 1..200.

### 3. Клиент — `DistantVehicleManager`

Синглтон, карта `entityId → DistantVehicle`, где `DistantVehicle` хранит:
локальный инстанс `VehicleEntity` (создан через
`EntityType.create(clientLevel)`, в `ClientLevel` НЕ добавляется), целевую
позицию/углы из последнего снапшота, время последнего обновления.

- **Приём пакета:** создать/обновить записи; проставить целевые значения;
  ghost'ы, отсутствующие в авторитетном списке, — удалить.
- **Клиентский тик:** плавная интерполяция текущих позиции/углов к целевым
  (за один интервал рассылки, ванильный механизм lerpSteps), запись
  `xo/yo/zo`, `turretYRotO/turretXRotO` и т.п. для partialTicks-лерпа
  рендерера.
- **Дедупликация:** если `clientLevel.getEntity(entityId) != null` (техника
  вошла в ванильный tracking range) — призрак не рендерится и удаляется.
- **Устаревание:** запись не обновлялась 3 интервала подряд — удалить
  (техника уничтожена, чанк выгружен или игрок уехал за радиус).
- **Очистка:** полная — при `ClientPlayerNetworkEvent.LoggingOut` и смене
  измерения (`ClientPlayerNetworkEvent.Clone` / смена level в тике).

### 4. Клиент — рендер

Подписка на `RenderLevelStageEvent` (stage `AFTER_ENTITIES`):

- Для каждого призрака: свой frustum-cull по AABB, затем рендер через
  `EntityRenderDispatcher.render(...)` с камерно-относительными координатами
  и partialTicks. `SbmVehicleRenderer` сам выберет LOD-модель (дистанция
  заведомо ≥ 32 блоков).
- Свет: `LightTexture.FULL_SKY` (packed sky=15/block=0) — реальные данные
  освещения чанка на такой дистанции недоступны.
- Дальняя граница отрисовки = `distantVehicleSyncRadius` (клиент читает
  радиус из факта наличия снапшотов — отдельная синхронизация конфига
  не нужна).

## Поток данных

```
Сервер: тикает реальную технику в прогруженных чанках
  └─ раз в N тиков: сбор в радиусе R → diff → DistantVehiclesMessage (S2C)
Клиент: DistantVehicleManager
  └─ обновляет призраков, интерполирует между снапшотами
RenderLevelStageEvent.AFTER_ENTITIES
  └─ SbmVehicleRenderer (LOD-модель) поверх LOD-террейна Voxy
       (depth-буфер общий — рельеф корректно перекрывает технику)
```

Стрельба по дальней технике работает без доработок: снаряды SBW — серверные
энтити, попадание считается по реальной технике на сервере.

## Обработка ошибок и краевые случаи

- Неизвестный `typeId` или `EntityType.create` вернул null (рассинхрон
  версий клиент/сервер) — снапшот молча пропускается.
- Пакет пришёл, когда `clientLevel == null` — игнорируется.
- Техника-пассажир другой техники (перевозка) — синхронизируется как
  отдельный снапшот по своей позиции; связь riding не передаётся.
- Туман: на 1–2 км ванильный fog в entity-шейдерах может полностью скрыть
  технику. Проверяется в игре; если подтвердится — при рендере призраков
  временно расширяются fog start/end (`RenderSystem.setShaderFog...`),
  по аналогии с обработкой тумана в Voxy.
- Игроки внутри техники не рендерятся (не синхронизируются) — принято.
- `distant_vehicle_sync_radius = 0` — сервер не шлёт пакеты, клиентский
  менеджер пуст, оверхеда нет.

## Тестирование

1. Сборка форка (`./gradlew build`).
2. Dev-сервер + dev-клиент (мультиплеер, Voxy на клиенте):
   - Поставить танк, отъехать/отлететь на 1+ км: техника видна поверх
     LOD-террейна, LOD-модель, позиция обновляется при движении (второй
     клиент или движущаяся техника).
   - Вернуться в ванильный tracking range: дубликата нет (призрак снят).
   - Уничтожить технику вдали: призрак исчезает ≤ 3 интервалов.
   - `radius=0`: пакетов нет, призраков нет.
   - Смена измерения/релог: призраки очищены.
3. Регрессия: обычный ближний рендер техники не затронут.

## Вне скоупа

- Изменения в Voxy (не требуются).
- Синхронизация пассажиров, анимаций ходовой, эффектов (дым/огонь) вдали.
- Техника в непрогруженных чанках.
- Ванильные мобы/игроки на дальней дистанции.
